# الخطة الرئيسية للمشروع — Watesly Travel AI

## 1. نظرة عامة

**Watesly Travel AI** منصة SaaS مستقلة ومتخصصة لشركات السياحة والسفر. تعمل كمساعد مبيعات سفر ذكي عبر واتساب، مع لوحة تحكم ويب عربية لإدارة الحملات والمحادثات والاستعلامات والعروض والحجوزات والتقارير.

هذا المشروع **مستقل بالكامل** عن أي منتج Watesly آخر، وله مستودع وبنية وبيئة تشغيل خاصة به.

---

## 2. المشكلة التي يحلها المنتج

شركات السفر تواجه اليوم:

- صعوبة متابعة استفسارات واتساب يدويًا وبسرعة.
- تكرار جمع بيانات الرحلة (مغادرة، وجهة، تواريخ، ركاب، ميزانية).
- تأخير في البحث عن الأسعار من عدة مزودين.
- غياب قواعد ربح موحدة وقابلة للتدقيق.
- ضعف عزل البيانات عند خدمة أكثر من فريق/فرع.
- انتقال غير منظم من الآلة إلى الموظف البشري.

المنصة تحوّل محادثة واتساب إلى مسار مبيعات منظم: فهم الطلب → استكمال البيانات → بحث حقيقي → تسعير آمن → عرض سعر → إعادة تحقق → حجز أو تحويل بشري.

---

## 3. الرؤية

أن تصبح المنصة نظام التشغيل التشغيلي لمبيعات السفر عبر واتساب للشركات الصغيرة والمتوسطة والكبيرة في المنطقة العربية، مع:

- عزل كامل لكل مؤسسة (`organizationId`).
- ذكاء اصطناعي لفهم الطلب فقط، وليس لاختراع الأسعار.
- محركات تسعير وقواعد ربح قابلة للتكوين.
- محولات مزودين (Adapters) قابلة للتوسع دون الاعتماد على مزود واحد.
- ضوابط صلاحيات صارمة للعمليات الحساسة (إصدار، دفع، تعديل أسعار).

---

## 4. مبادئ تصميم غير قابلة للتفاوض

| المبدأ | التفصيل |
|---|---|
| استقلال المشروع | لا اعتماد على كود أو أسرار أو بيئات مشروع Watesly الأساسي |
| Multi-Tenant | كل سجل تشغيلي مربوط بـ `organizationId` مع عزل صارم |
| Adapter-first | لا اعتماد على Amadeus أو أي مزود واحد؛ كل مزود خلف واجهة Adapter |
| أسعار حقيقية فقط | الذكاء الاصطناعي لا يخترع أسعارًا؛ المصدر مزود حقيقي أو مزود تجريبي واضح (`mock`) |
| فصل التكلفة عن البيع | النظام يحتفظ بـ تكلفة / بيع / ربح داخليًا؛ العميل يرى سعر البيع فقط |
| إعادة التحقق | قبل تأكيد الحجز يُعاد التحقق من السعر والتوافر |
| صلاحيات حساسة | الإصدار والدفع وتجاوز التسعير تحتاج موافقة/صلاحية صريحة |
| العربية أولًا | واجهة لوحة التحكم عربية (RTL) كمسار أساسي |

## 5. أصحاب المصلحة

- **مالك شركة السفر / المدير**: الاشتراك، الإعدادات، التسعير، التقارير.
- **موظف المبيعات**: المحادثات، العروض، الحجوزات، التحويل البشري.
- **المشرف / الأدمن**: المستخدمون، الصلاحيات، مزودو السفر، واتساب.
- **العميل النهائي**: يتفاعل عبر واتساب فقط.
- **مشغّل المنصة (Platform Admin)**: إدارة الاشتراكات والدعم على مستوى SaaS.

---

## 6. عرض القيمة

1. استقبال وفهم استفسارات السفر تلقائيًا عبر واتساب.
2. استخراج بيانات الرحلة وسؤال العميل عن الناقص.
3. البحث عبر مزودي سفر متعددين عبر طبقة Adapters.
4. تطبيق قواعد الربح وإنشاء عرض سعر احترافي.
5. إعادة التحقق قبل الحجز وتقليل أخطاء التسعير.
6. تحويل آمن للموظف البشري عند الحاجة.
7. تقارير تشغيلية ومبيعات لكل مؤسسة.

## 7. النطاق الوظيفي الرئيسي

### قنوات التواصل
- واتساب Cloud API: حملات، رسائل واردة/صادرة، قوالب.
- لوحة تحكم ويب للموظفين والمديرين.

### دورة المبيعات
1. حملة أو رسالة واردة أو استعلام مباشر.
2. إنشاء/ربط محادثة وعميل.
3. استخراج نية السفر وبيانات الرحلة عبر AI.
4. استكمال البيانات الناقصة بالحوار.
5. بحث الخدمات عبر المزودين.
6. تطبيق قواعد التسعير.
7. إنشاء عرض سعر وإرساله.
8. إعادة التحقق عند القبول.
9. إنشاء طلب حجز / حجز.
10. تحويل بشري عند التعقيد أو الطلب.

### أنواع الخدمات المدعومة (مستهدف)
- طيران دولي / داخلي
- فنادق
- تأمين سفر
- تأجير سيارات
- استقبال وتوصيل (Transfers)
- مواصلات مرتبطة بالرحلة

## 8. البنية التقنية المقترحة (ملخص)

- **Monorepo** مع Turborepo
- **TypeScript** في كل الطبقات
- **Next.js** → `apps/web`
- **NestJS** → `apps/api`
- **Workers** → `apps/worker` (طوابير Redis)
- **PostgreSQL + Prisma**
- **Redis** للتخزين المؤقت والطوابير
- **Docker** للتطوير والنشر لاحقًا
- حزم مشتركة: `ui`, `database`, `auth`, `config`, `shared`, `ai-core`, `whatsapp-core`, `travel-core`, `pricing-engine`, `provider-sdk`

تفاصيل أعمق في [`ARCHITECTURE.md`](./ARCHITECTURE.md).

## 12. ما هو خارج هذه المرحلة

هذه المرحلة **وثائق وهيكل فقط**. لا يشمل:

- تثبيت الحزم
- بناء الواجهات
- ترحيلات قاعدة البيانات
- ربط واتساب حقيقي
- ربط مزودي سفر حقيقيين
- النشر أو الاتصال بأي سيرفر قائم
